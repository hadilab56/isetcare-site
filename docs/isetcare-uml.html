Un seul serveur, deux clients

Une réclamation signalée depuis le téléphone apparaît aussitôt sur le site : les deux écrivent dans la même API et la même base.

Offre gratuite

Le serveur Render s'endort après 15 minutes sans visite ; la requête suivante prend environ une minute. Les photos du dossier uploads/ sont perdues à chaque redémarrage.

Règles de gestion

Un équipement a un QR code unique. Une réclamation concerne un seul équipement. Une intervention appartient à une réclamation (composition) et est réalisée par un technicien.

Maintenance et remplacement

La prochaine maintenance se calcule depuis la fréquence du type d'équipement. La recommandation compare le coût cumulé des réparations au coût de remplacement ; l'administrateur décide.

Écarts entre le modèle et le code

Le code respecte le diagramme, avec ces différences d'implémentation. Elles sont bonnes à connaître si le jury compare le modèle et la base de données.

Point du modèleDans le codePourquoi
Héritage Déclarant / Administrateur / TechnicienUne seule table utilisateurs avec la colonne role ; les attributs propres à un rôle restent vides pour les autres.Héritage « table unique » : plus simple pour la connexion et les requêtes.
Administrateur « affecte » ReclamationLa réclamation stocke le technicien affecté (technicien_id) ; l'administrateur qui a affecté n'est pas enregistré.Seul l'administrateur peut affecter (règle de sécurité), donc son identité n'est pas nécessaire au traitement.
Types int, doubleLong pour les identifiants, BigDecimal pour les montants.Identifiants générés par PostgreSQL ; montants exacts sans erreur d'arrondi.
Multiplicités « 1 » vers Salle, TypeEquipement, TechnicienColonnes facultatives (0..1) : un équipement peut être créé avant d'avoir une salle, une intervention ou une maintenance avant d'avoir un technicien.Souplesse à la saisie ; le diagramme décrit le cas normal.
motDePasse : StringStocké chiffré (BCrypt), jamais renvoyé par l'API.Sécurité des comptes.
—Ajout : assistant de discussion IA (Gemini), sans nouvelle classe persistée.Aide aux utilisateurs du site ; la conversation n'est pas enregistrée.

Le scénario principal depuis la page « Signaler une panne » du site (US11, US31, US26). L'application suit le même chemin par /api/ia/analyser et /api/mobile/reclamations, en général après le scan du QR code (US10).

Diagramme de séquence : affectation et traitement

La suite, entre les trois rôles (US14, US18, US17, US19, US16, US33). Le technicien peut faire les étapes 4 à 9 sur le site ou dans l'application.
