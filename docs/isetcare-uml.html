One backend, two clients

A breakdown reported from the phone appears on the website at once, because both write to the same API and database.

Free-tier behaviour

The Render server sleeps after 15 minutes without traffic; the first request then takes about a minute. Photos in uploads/ are lost when it restarts.

Déclarant web app

Creates reports (POST /api/reclamations is reserved to this role) and only ever sees their own.

Technicien web app

Works only on reports assigned to them. A report cannot be resolved without at least one intervention.

Administrateur web app

Owns assignment, priority and closing, all reference data, maintenance planning and statistics.

Sequence diagram: report a breakdown

The main flow, from the website's "Signaler une panne" page. The app follows the same path through /api/ia/analyser and /api/mobile/reclamations, usually after scanning the equipment's QR code.

sequenceDiagram
  autonumber
  actor D as Déclarant
  participant W as Website (React)
  participant A as API (Spring Boot)
  participant IA as IaService
  participant G as Gemini
  participant DB as PostgreSQL
  participant N as NotificationService
  D->>W: Describes the problem, picks the equipment
  W->>A: POST /api/ai/analyze {description, equipementId}
  A->>IA: analyser(description, type)
  alt GEMINI_API_KEY set
    IA->>G: generateContent (JSON prompt)
    G-->>IA: categorie, typePanne, priorite, confiance
  else no key or Gemini error
    IA->>IA: RulesClassifier (keywords)
  end
  Note over IA: Smoke, sparks, burning smell → URGENTE, always
  IA-->>A: AiAnalysis
  A-->>W: suggestion
  W-->>D: Pop-up: category, priority, probable cause
  D->>W: Confirms and sends (optional photo)
  W->>A: POST /api/reclamations (multipart, JWT)
  A->>DB: INSERT reclamation (NOUVEAU) + analyse_ia
  A->>DB: equipement.etat = EN_PANNE
  A->>N: notifierAdmins(NOUVELLE_RECLAMATION)
  opt Repeated breakdowns on this equipment
    A->>N: notifierAdmins(PANNES_FREQUENTES)
  end
  N->>DB: INSERT notifications
  A-->>W: 201 Created
  W-->>D: Report listed under "Mes réclamations"

Sequence diagram: assignment and repair

What happens after the report exists, across the three roles. The technician can do steps 4 to 9 from the website or from the app.

sequenceDiagram
  autonumber
  actor AD as Administrateur
  actor T as Technicien
  actor D as Déclarant
  participant A as API
  participant DB as PostgreSQL
  AD->>A: PATCH /api/reclamations/{id}/affectation {technicienId}
  A->>DB: technicienAffecte = T, statut = AFFECTEE
  A-->>T: Notification NOUVELLE_RECLAMATION
  T->>A: PATCH /api/reclamations/{id}/statut EN_COURS
  A-->>D: Notification CHANGEMENT_STATUT
  T->>A: POST /api/reclamations/{id}/interventions {diagnostic, action, cout}
  A->>DB: INSERT intervention
  T->>A: PATCH /api/reclamations/{id}/statut RESOLU
  A->>DB: check ≥ 1 intervention, statut = RESOLU, equipment state synced
  A-->>D: Notification CHANGEMENT_STATUT
  AD->>A: PATCH /api/reclamations/{id}/cloture
  A->>DB: statut = CLOTURE
  A-->>D: Notification CHANGEMENT_STATUT
  opt Equipment keeps failing
    AD->>A: POST /api/ai/recommend-replacement {equipementId}
    A-->>AD: REPARER / SURVEILLER / REMPLACER with reasons (cost ratio, breakdowns in 12 months, age)
  end
